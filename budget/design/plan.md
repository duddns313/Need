# 부부 공동 가계부 — 설계서 v1 (승인 대기)

> 뱅크샐러드 엑셀 2개(남편/아내)를 올리면 → 정제·합산 → 대시보드 + 시골쥐 스타일 올인원 관리표(.xlsx) 출력
> 참고: [시골쥐 올인원 자산관리표](https://jinjeongsung.com/shop_view/?idx=96) — 가계부·고정비·카드·주식·부동산을 한 파일에서 보고, 부부 가계부를 합쳐 볼 수 있는 구조

## 0. 왜 "엑셀만"으로는 안 되는가 (실제 데이터 분석 결과)

업로드해 준 파일(2025-08-01 ~ 2026-08-01, 1,706건)을 열어보고 나온 사실:

| 발견 | 숫자 | 의미 |
|---|---|---|
| 뱅샐이 "지출"로 찍은 건수 | 1,294건 / 합계 약 -1억 1천만원 | 이걸 그대로 쓰면 월 지출이 1,300만원으로 나옴 |
| 그중 `금융` 대분류 | 146건 / -5,512만원 | **카드대금·송금·대출상환**이 지출로 잡혀 있음 → 실제 소비 아님 |
| `이체/내계좌이체` | 190건 | 내 통장 → 내 통장. 집계 제외 대상 |
| `수입/금융수입` | 99건 / +6,457만원 | 대부분 **이자·환급·정산금**. 급여(14건)와 섞이면 소득이 왜곡됨 |
| **`지출/미분류`** | **342건 (지출의 26%)** | 배민 35건, SKT 24건, 병원, 김밥집, 편의점… 전부 분류 가능한데 비어 있음 |

설계서를 쓴 뒤 분류 엔진을 실제로 돌려봤더니 **책상 위에서는 안 보였을 버그가 두 개** 나왔다.
둘 다 설계 자체를 바꾼 발견이라 여기 남긴다.

1. **키워드 규칙이 거래 방향을 무시했다.** 회사('공항철도(주)')에서 들어온 급여 5,400만원이
   내용에 '철도'가 들어 있다는 이유로 **교통비(지출)** 로 잡혔다.
   → 규칙 순서를 고쳐 **방향(수입/지출)을 먼저 확정**하고, 수입 거래에는 수입 카테고리만 붙인다.
2. **뱅샐은 급여를 급여로 안 준다.** 위 5,400만원은 원본에서 `금융수입/미분류`였다.
   → 금액·반복 횟수로 정기 수입을 찾아 급여로 승격하고, 무엇을 올렸는지 화면에 보여줘 되돌릴 수 있게 한다.

고친 결과: 미분류 342건 → 162건, 월 지출이 1,300만원대에서 **300~600만원대**로 내려왔다(= 실제 소비 수준).

→ 즉 **뱅샐 원본을 그대로 시트에 붙이면 가계부가 아니라 노이즈**다.
이 프로젝트의 진짜 작업은 예쁜 표를 그리는 게 아니라 **정제 규칙 엔진**이다. 그리고 그 규칙은 매달 새 파일을 올릴 때마다 다시 돌려야 하므로, 손으로 하는 엑셀 작업이 아니라 **코드가 해야 한다.**

### 그래서 결과물 형태

**로컬 웹앱(Flask) + 엑셀 출력, 둘 다.**

```
python budget/run.py      →  브라우저 자동 오픈 (localhost:8734)
  [1] 업로드 화면 : 남편 엑셀 / 아내 엑셀 각각 드래그앤드롭
  [2] 정리 화면   : 자동분류 결과 확인, 미분류 건 한 번에 처리
  [3] 대시보드    : 기준월 선택 → 부부합산/개인별 전환
  [4] 버튼        : "올인원 관리표 내려받기" → .xlsx (수식 살아있는 파일)
```

- 인터넷 안 씀. 파일은 내 PC 안에서만 돌아감(금융 데이터라 이게 중요).
- 기존 저장소의 RSMS 앱과 같은 스택(Flask + openpyxl + waitress)이라 의존성 추가 없음.
- **엑셀도 그대로 나온다.** 앱 안 켜고 싶은 날엔 xlsx만 열면 됨. xlsx는 값 박제가 아니라 SUMIFS 수식이라 손으로 한 줄 추가해도 숫자가 따라 움직인다.

## ① 시트/화면 구성 & 카테고리 체계

### 웹앱 화면

| 화면 | 역할 | 사용자가 하는 일 |
|---|---|---|
| 업로드 | 부부 각각의 뱅샐 엑셀 등록 | 파일 2개 던지기 (1개만 올려도 동작) |
| 정리 | 자동분류 결과 + 미분류 큐 | "이건 식비" 클릭 → 규칙으로 저장돼 다음 달엔 자동 |
| 대시보드 | 월 요약·추이·예산 대비·순자산 | 보기만 |
| 설정 | 예산, 고정비 목록, 소유자 이름, 분류 규칙 | 초기 1회 |

### 출력 엑셀 시트

| 시트 | 역할 | 입력 주체 |
|---|---|---|
| `사용법` | 어디를 만지고 어디는 건드리면 안 되는지 | 읽기 전용 |
| `기준정보` | 기준월·시작잔액·카테고리·예산·고정비목록·소유자명 | **사용자(노란칸)** |
| `거래내역` | 정제된 거래 1행씩 (소유자 열 포함) | 앱이 채움 + 손으로 추가 가능 |
| `월집계` | 월 × 카테고리 × 소유자 SUMIFS | 수식 전용 |
| `대시보드` | 이번 달 요약·차트·예산게이지 | 수식 전용 |
| `자산부채` | 양쪽 뱅샐현황 합산 → 순자산 | 앱이 채움 |
| `고정비체크` | 이번 달 안 빠진 고정비 표시 | 수식 전용 |

### 카테고리 체계 (시골쥐식 3분법: 고정비 / 변동비 / 저축·투자)

가계부가 실패하는 이유는 카테고리가 많아서다. **대분류 4성격 × 세부 18개**로 고정.

| 성격 | 카테고리 | 뱅샐 원본에서 오는 곳 |
|---|---|---|
| **수입** | 급여 | `수입/급여` |
| | 부수입 | `수입/기타수입`, `수입/용돈` |
| | 금융소득(이자·배당) | `수입/금융수입` |
| **고정비** | 주거·관리비 | 내용에 `관리비`, `월세`, `전기`, `가스` |
| | 통신 | `SK텔레콤`, `KT`, `LG유플러스` |
| | 보험 | `금융/보험` |
| | 구독료 | `온라인쇼핑/서비스구독`, `자동결제`, 디즈니플러스 등 |
| | 대출이자 | `금융/이자·대출` 중 이자분 |
| **변동비** | 식비·외식 | 우아한형제들/배민, 맥도날드, 김밥, 식당, 카페… |
| | 생활·마트 | `생활/*`, GS25·CU·이마트 |
| | 교통 | `교통/*` (스윙·지바이크·택시·철도) |
| | 의료·건강 | `의료/건강`, 병원·약국 |
| | 문화·여가 | `문화/여가` |
| | 쇼핑 | `온라인쇼핑/인터넷쇼핑` |
| | 경조·선물 | `경조/선물` |
| | 여행·숙박 | `여행/숙박` |
| | 자동차 | `자동차` |
| | 교육 | `교육/학습` |
| | 세금·기타 | `금융/세금·과태료` |
| **저축·투자** | 저축·예금 | `이체/저축`, 청약 |
| | 투자 | 증권 입금, 연금 |
| | 대출원금상환 | `대출상환(...)` |
| **제외(집계 안 함)** | 내계좌이체 | `이체/내계좌이체` |
| | 카드대금 | `금융/카드`, `이체/카드대금` |
| | **부부간 이체** | 자동 매칭 (아래 ③) |
| | 페이 충전 | `네이버페이충전`, `카카오페이 머니` |

> **핵심 원칙:** 이체·카드대금·페이충전·부부간송금은 지출이 아니다. 저축·투자는 지출이 아니라 별도 축이다.
> 이걸 안 박아두면 "이번 달 1,300만원 썼네"라는 거짓말이 나온다.

## ② 거래 스키마 & 입력 규칙

정제 후 `거래내역` 시트 = 앱 내부 데이터 모델 = 엑셀 열.

| 열 | 형식 | 필수 | 규칙 |
|---|---|---|---|
| 날짜 | 진짜 날짜값 | O | 카드는 **사용일** 기준 (뱅샐 원본 그대로) |
| 소유자 | 남편 / 아내 (드롭다운) | O | 업로드한 파일에 따라 자동 부여 |
| 구분 | 수입/지출/저축/제외 | O | 4값 고정 |
| 성격 | 고정비/변동비/저축투자/수입/제외 | O | 카테고리에서 자동 |
| 카테고리 | 위 18개 드롭다운 | O | 기준정보 참조 |
| 내용 | 텍스트 | - | 뱅샐 `내용` 그대로 (검색용) |
| 금액 | **양수 정수** | O | 부호로 수입/지출 구분하지 않음 — `구분` 열이 그 역할 |
| 결제수단 | 텍스트 | - | 뱅샐 원본 |
| 공동/개인 | 공동 / 개인 | O | 정산용 (아래 ③) |
| 메모 | 텍스트 | - | 자동분류 근거·환불 사유 |

정해두는 규칙:
- **환불**: 음수 금액 1줄로 적는다(수입으로 올리지 않는다). 해당 카테고리 합계가 그만큼 줄어든다.
- **할부**: 사용일에 총액 1줄. 뱅샐이 그렇게 주기 때문에 그대로 따른다.
- **중복 업로드**: `날짜+시간+금액+내용+소유자` 해시로 중복 제거. 같은 파일 두 번 올려도 두 배 안 된다.
- **기간 겹침**: 지난달 파일과 이번달 파일이 겹쳐도 위 해시로 흡수.

## ③ 자동 계산 규칙

### (a) 분류 엔진 (앱, `rules/default_rules.json`)
우선순위 순으로 첫 매칭 채택 — 항상 이 순서:
1. 사용자가 손으로 확정한 건 (`내용` 완전일치) → 무조건 우선
2. **거래 방향 확정** — 수입 거래는 수입 카테고리(급여/부수입/금융소득) 안에서만 결정
3. 부부간 이체 매칭 (아래 b)
4. 제외 규칙 (카드대금·내계좌이체·페이충전)
5. 내용 키워드 규칙 (배민→식비, SKT→통신 …)
6. **업종 접미사 정규식** (`~빵집`, `~횟집`, `~카레`, `~자판기` …)
7. 뱅샐 대/소분류 매핑
8. 남으면 `미분류` → 정리 화면 큐로

실측 감소: **342건 → 162건**(2~5번) **→ 132건**(6번 추가).

### (a-2) 남은 미분류: 조회 먼저, 추측은 나중

132건에서 배우자 송금(윤영운 13건)을 빼면 **118건 / 고유 상호 107개**가 남는다.
`알레스구떼`, `가또블랑코`, `씨샵인더룸`, `라메르#` — 상호 이름은 무한해서 규칙으로는 원리적으로 못 잡는다.

**하지만 이건 추측할 문제가 아니다.** 전부 실제로 존재하는 가게이고, 지도에 업종이 등록돼 있다.
그래서 순서는 **사실 조회 → 추측 → 사람** 이다.

| 단계 | 하는 일 | 근거 |
|---|---|---|
| ① 지도 조회 (`places.py`) | 상호명으로 카카오/네이버 지역검색 → 업종 문자열 | **사실**. 등록된 업종 |
| ② Claude (`ai_classify.py`) | 지도에 없는 것만 (온라인 결제, 폐업, 무인점포) | 추측. 확신도 함께 |
| ③ 사용자 | 확신도 낮은 것 + 둘 다 실패한 것 | 최종 판단 |

**① 지도 조회 설계**

- 카카오 `GET https://dapi.kakao.com/v2/local/search/keyword.json` (`Authorization: KakaoAK {키}`)
  또는 네이버 `GET https://openapi.naver.com/v1/search/local.json` (`X-Naver-Client-Id/Secret`)
- 응답의 업종은 계층 문자열로 온다 — 카카오 `category_name`, 네이버 `category`:
  `"음식점 > 카페 > 디저트카페"`, `"서비스,산업 > 자동차 > 주차장"`
- **계층을 뒤에서부터 읽는다.** 앞머리만 보면 `서비스,산업 > 자동차 > 주차장`이 엉뚱한 데로 간다
  (실제로 그 버그가 났고 테스트로 잡았다). 마지막 칸이 진짜 업종이다.
- ⚠️ 카카오 `category_group_code`(FD6/CE7/…) 표는 **공식 문서가 403이라 확인하지 못했다.**
  그래서 코드 표에 의존하지 않고 계층 문자열로만 매핑한다.
- **상호명 정제**가 조회 성공률을 좌우한다. 카드 명세서 상호는 법인격·지점·결제대행사가 뒤섞여 있다:
  | 원본 | 조회 후보 (순서대로) |
  |---|---|
  | `(주)빅바이트컴퍼니 잠바주스 서울역점` | 빅바이트컴퍼니 잠바주스 서울역점 → 빅바이트컴퍼니 잠바주스 → **잠바주스** |
  | `엔제리너스잠실샤롯데1F점/롯데컬처웍스(주` | **엔제리너스잠실샤롯데** |
  | `피터팬/주식회사피터팬식품` | **피터팬** |
  | `객기(gaekgi)` | **객기** |
  실측: 미분류 107개 전부 후보 생성 성공, 상호당 평균 1.6개(최대 7개).
- **캐시**: `data/places_cache.json`. 못 찾은 것도 기록해 재조회하지 않는다. 상호 하나당 평생 한 번.

**② Claude 설계** — 지도에서 못 찾은 것만 넘어온다.

| 항목 | 설계 |
|---|---|
| 보내는 것 | **고유 상호명만.** 금액·날짜·계좌번호·카드번호는 나가지 않는다 |
| 호출 횟수 | 60개씩 배치. 결과는 `user_rules.json`에 저장돼 다음 달부터 자동 |
| 출력 형식 | JSON Schema로 카테고리를 **지출 16종 enum으로 강제** — 수입/이체로 잘못 옮기는 사고를 구조적으로 차단 |
| 확신도 | 0.7 미만은 자동 확정 안 함. 사람 이름처럼 보이면 0.3 이하로 답하도록 지시 |

**키가 없으면 ①②를 건너뛴다.** 규칙 엔진만으로도 앱은 완전히 동작한다(132건 미분류 상태로).

**남는 건 0으로 만들지 않는다** — 애매한 건 찍지 말고 사용자에게 물어보는 게 맞다.

### (b) 부부간 이체 자동 상계
> 남편이 아내에게 50만원 송금 → 남편 파일엔 지출 50만, 아내 파일엔 수입 50만.
> 그냥 합치면 **지출 50만 + 수입 50만이 허위로 잡힌다.**

매칭 조건: `금액 동일` AND `날짜 차이 ≤ 1일` AND `한쪽 지출/이체 + 다른쪽 수입` AND `내용에 상대방 이름 또는 이체성 키워드`
→ 양쪽 다 `제외`로 마킹, 정리 화면에 "부부간 이체 N건 상계함" 표시(사용자가 되돌릴 수 있음).

### (c) 엑셀 수식 (값 박제 금지)
- 월키: `=EOMONTH(A2,0)`
- 이번 달 부부합산 소비지출: `=SUMIFS(금액,구분,"지출",월키,기준월)`
- 남편만: `=SUMIFS(금액,구분,"지출",소유자,"남편",월키,기준월)`
- 카테고리 예산 대비: `=IFERROR(실적/기준정보!예산,0)`
- 저축률: `=IFERROR((수입-지출)/수입,0)` — 0 나눗셈 방어
- 고정비 체크: `=IF(COUNTIFS(카테고리,항목,월키,기준월)=0,"미납","OK")`
- 이월 잔액: `전월 잔액 + 당월 수입 − 당월 지출 − 당월 저축`, 첫 달은 `기준정보!시작잔액`
- 하루 가용액: `(예산합계 − 지출합계) / 남은 일수`
- 함수는 Excel 2007 세대만: `SUMIFS COUNTIFS INDEX MATCH IFERROR SUMPRODUCT EOMONTH TEXT`
  (`XLOOKUP/FILTER/UNIQUE`는 안 씀 — 구버전·모바일에서 `#NAME?` 남)

### (d) 부부 정산
- 공동비용 총액 중 남편이 낸 금액 / 아내가 낸 금액
- 분담 기준 2택 (설정에서 선택): **반반** 또는 **소득 비례**
- 결과: "이번 달 아내가 173,000원 더 냈음 → 정산 필요"

## ④ 입력 체계

**웹앱**
- 업로드: 파일 2칸(남편/아내), 라벨은 설정에서 실제 이름으로 변경 가능
- 정리 화면: 미분류 건을 `내용`으로 묶어서 보여줌 → 한 번 클릭하면 그 상호의 과거·미래 건 전부 분류됨
- 되돌리기: 자동 상계·자동 분류는 전부 개별 해제 가능

**엑셀**
- 노란 칸 = 반드시 채우는 값(기준월, 시작잔액, 예산) / 파랑 = 손으로 채워도 되는 칸 / 검정 = 수식
- 드롭다운은 데이터 유효성 목록, 원본은 `기준정보`의 명명 범위(여유 범위로 잡아 카테고리 추가 대응)
- `월집계`·`대시보드` 시트는 잠금, `거래내역` 입력열만 열어둠
- 새 행 추가해도 잡히도록 수식은 3,000행까지 선반영

## ⑤ 대시보드 구성 (시안 있음 → `budget/design/mockup.html`)

시골쥐 가계부 시트의 배치를 따른다: **왼쪽 거래 / 가운데 가로막대 3블록 / 오른쪽 카테고리 표**,
그리고 기준월 셀(엑셀) / 기준월 드롭다운(웹) **하나만 바꾸면 화면 전체가 따라 움직인다.**

1. **상단 바** — 보기 전환(부부 합산·남편·아내) / 기준월 / 파일 업로드 상태 2칸
2. **KPI 4장** — 수입 / 지출 / 저축·투자 / 저축률(히어로), 전월 대비 증감
3. **정제 리포트** — "뱅샐 원본에서 뺀 금액" 카드. 왜 앱 숫자가 뱅샐과 다른지 여기서 설명한다
4. **가로막대 3블록** — 이달 수입(주황 배경) / 이달 지출(파랑) / 이달 저축·투자(초록), 시골쥐 배치 그대로
5. **12개월 추이** — 수입·지출·저축 3선, 열 단위 크로스헤어 툴팁 + 표 보기
6. **카테고리별 지출** — 남편/아내 누적 스택 (누가 어디에 쓰는지)
7. **고정비 vs 변동비** — 누적 막대 + 고정비 항목 표
8. **순자산** — 총자산/총부채 막대, 투자 평가금액·수익률·대출잔액
9. **정리 큐** — 급여 오분류·배우자 송금 후보·미분류를 클릭 한 번으로 처리
10. **예산 대비 게이지** — 초과 카테고리 빨강 (예산 입력 후 표시)
11. **정산 카드** — 이번 달 공동비용 분담 차액

### 색 규칙 (전 화면·엑셀 공통, 한 번 정하고 안 바꾼다)

| 뜻 | 라이트 | 다크 | 근거 |
|---|---|---|---|
| 수입 | `#eb6834` 주황 | `#d95926` | 시골쥐 시트의 수입=살구색을 잇는다 |
| 지출 | `#2a78d6` 파랑 | `#3987e5` | 시골쥐 시트의 지출=파랑 |
| 저축·투자 | `#1baf7a` 초록 | `#199e70` | 시골쥐 시트의 저축=연두 |
| 아내(스택 2번째) | `#86b6ef` 연파랑 | `#1c5cab` | 같은 파랑의 다른 명도 — 둘 다 '지출'이라는 뜻은 유지 |
| 부채 | `#e34948` 빨강 | `#e66767` | 자산↔부채는 방향이 반대인 값이라 대비 쌍으로 |

- 색맹 검증기를 돌려서 통과시킨 조합이다 (수입/지출/저축 3색: CVD ΔE 9.2 라이트 / 9.4 다크, 기준 8 이상).
- 축을 두 개로 나눈 차트는 만들지 않는다. 없는 상관관계가 보이기 때문.
- 색만으로 뜻을 전달하지 않는다 — 모든 막대에 이름과 금액을 직접 붙이고, 추이 차트엔 표 보기를 단다.
- 다크 모드는 라이트를 뒤집은 게 아니라 다크 표면에 맞춰 따로 고른 값이다.

## ⑥ 완료 기준 (= 검수 스킬의 테스트 항목)

**정제 정확성**
- [ ] 뱅샐 원본 1,706건을 넣으면 카드대금·내계좌이체·페이충전이 소비지출 합계에 **1원도** 포함되지 않는다
- [ ] 정제 후 월 소비지출이 원본 "월지출 총계"보다 작고, 그 차액이 (제외+저축투자) 합계와 **정확히 일치**한다
- [ ] 미분류 지출이 342건 → 50건 이하로 줄어든다
- [ ] 같은 파일을 두 번 올려도 거래 건수·합계가 변하지 않는다
- [ ] 부부간 이체를 상계하면 부부합산 수입과 지출이 동시에 그 금액만큼 줄어든다

**부부 합산**
- [ ] 파일 2개를 올리면 모든 거래에 소유자가 붙고, 합산 = 남편분 + 아내분이 정확히 일치한다
- [ ] 파일 1개만 올려도 오류 없이 동작한다
- [ ] 개인별 보기로 전환하면 그 사람 거래만 집계된다

**엑셀 산출물**
- [ ] `거래내역`에 지출 1줄 추가하면 `대시보드` 이번 달 지출이 정확히 그만큼 늘어난다
- [ ] 기준월 셀을 바꾸면 요약·차트가 전부 그 달 기준으로 바뀐다
- [ ] 카테고리 칸은 드롭다운으로만 입력되고 목록 밖 값은 거부된다
- [ ] 환불(음수) 거래를 넣으면 해당 카테고리 합계가 그만큼 줄어든다
- [ ] 예산 초과 카테고리가 빨갛게 표시된다
- [ ] 거래가 0건이어도 `#DIV/0!` 없이 전부 0으로 보인다
- [ ] 마지막 행 아래 새 행을 추가해도 집계에 자동 반영된다
- [ ] **파일 전체 수식 오류 0건** (`#NAME? #REF! #VALUE! #DIV/0!`)

**자산**
- [ ] 순자산 = (남편 총자산 + 아내 총자산) − (남편 총부채 + 아내 총부채) 로 검산된다

## 기술 기본값

- `.xlsx` 단일 파일, **매크로 없음** (모바일 엑셀·구글시트에서도 열림)
- openpyxl로 **수식을 쓴다**, 파이썬으로 계산한 숫자를 박아넣지 않는다
- 날짜는 진짜 날짜값, 금액은 정수, 표시서식 `₩#,##0`, 퍼센트는 분수 저장
- 모든 가정(예산·시작잔액·기준월·분담비율)은 `기준정보`의 이름 붙은 셀 1개 — 하드코딩 금지
- 입력 시트(거래내역)와 계산 시트(월집계/대시보드)를 섞지 않는다
- 저장 위치: `budget/data/` (JSON). 업로드 원본은 보관하지 않고 파싱 후 폐기 옵션 제공
